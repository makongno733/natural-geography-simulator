# 账号服务备份、监控与发布检查

> 本文提供仓库内可运行的备份/恢复检查和发布面探针。本文档与脚本不访问生产环境；正式站、GitHub Pages 镜像和账号 API 的线上验收须由有权限的维护者在获批后执行。

## SQLite 备份与恢复演练

账号服务使用 SQLite WAL。不要用 `cp` 直接复制正在运行的数据库文件；维护脚本调用 SQLite 在线备份 API，并在完成后执行 `integrity_check` 与 `foreign_key_check`。

1. 在账号服务器的私有环境变量中配置 `ACCOUNT_DB_PATH` 和 `ACCOUNT_BACKUP_DIR`。备份目录应位于与数据库目录分离、访问受限且有独立故障域的存储卷；不要把数据库或备份提交到仓库。
2. 运行 `pnpm account:backup`。脚本要求源数据库已存在，备份目录不得位于数据库目录内；输出一个唯一备份文件路径，并以目录 `0700`、文件 `0600` 权限保存。
3. 将生成的备份文件路径交给 `pnpm account:restore-check -- <备份文件路径>`。该命令在系统临时目录恢复副本，检查 SQLite 完整性及外键，再删除临时副本；它不会写入或覆盖活动数据库。
4. 维护者应另行定期在隔离的恢复环境完成应用级恢复演练：从备份恢复到空白测试实例、运行 `pnpm account:migrate` 和 `node scripts/verify-deploy-ready.mjs`，验证登录/评论等关键读写后销毁测试数据。未完成该演练前，不得声称生产恢复能力已验证。

仓库不包含生产调度、备份保留或密钥管理配置。上线前由服务负责人配置定期备份、加密传输/静态加密、访问控制、异地副本与保留期，并记录最近一次成功恢复演练的日期和责任人。备份脚本会覆盖备份目录权限为仅目录所有者可访问；请先确认该目录由账号服务维护者拥有。

## 健康检查与告警

- `GET /api/health` 执行一次 SQLite 查询；数据库不可查询时返回 HTTP 503，不返回内部错误细节。它只证明 HTTP 进程与数据库当下可用，不代表登录邮件、AI 服务、事件源同步或前端全部可用。
- 监控系统应对账号 API 的 `/api/health` 做 HTTPS 探测。可将“连续 3 次超时/非 200”作为初始告警草案，恢复 2 次成功后清除；这是建议的探测策略，不是已测得的服务级目标。须由维护者结合实际服务商能力确认。
- 本仓库没有绑定特定云监控服务或告警凭据，故尚未安装外部告警规则。探测失败应进入维护团队实际使用的告警渠道；不要把仅有 HTTP 健康探测表述为数据库备份或地理数据源健康证明。

## 发布后检查三类服务

`pnpm deploy:verify:surfaces` 检查正式站 HTML/站点地图、GitHub Pages 镜像是否指向正式站，以及账号 API 数据库健康端点。脚本默认拒绝出站请求，须在获批的发布验收环境显式配置全部地址并开启网络门：

```sh
DEPLOYMENT_CHECK_ALLOW_NETWORK=1 \
PUBLIC_SITE_URL=https://geo.kongnoma279.com/ \
PAGES_MIRROR_URL='<维护者填写 GitHub Pages 镜像 URL>' \
ACCOUNT_API_URL='<维护者填写账号 API 根 URL>' \
pnpm deploy:verify:surfaces
```

任何一项失败都会返回非零退出码，可由维护者接入既有发布门禁/告警。当前分支未运行该命令访问线上服务；不得替换成猜测的镜像或账号 URL。正式站与镜像必须分别验证，不以一次成功代替另一项。

## 审核、滥用防护与账号安全现状

- 社区举报与事件纠错均通过审核队列处理；现有社区发布、回复、举报与事件纠错接口已有账号级频率限制。课程助手有每日/每分钟请求上限，但其计数保存在单进程内存，多副本或重启场景仍需共享限流方案。
- 讨论与回复均提供作者修改、管理员修改和纠错/举报入口。管理权限通过 `GET /api/community/me` 查询数据库角色，不从会话中未经确认的 `role` 推断。回复举报队列可直达原讨论的对应回复；匿名用户只能阅读，提交反馈须登录。
- `PATCH /api/community/posts/:id` 与 `PATCH /api/community/replies/:id` 保存修改前的公开观点、编辑者和时间；界面携带 `expectedUpdatedAt`，过期草稿返回 409 而不覆盖。未改变内容不新增修订；修改已采纳回复会取消采纳，须由提问者重新确认。`DELETE /api/community/replies/:id` 撤回回复，作者或管理员可执行。
- 讨论与回复的 `/revisions` 公开端点仅对仍公开的内容提供记录，回复还要求其父讨论公开。隐藏或删除后，正文与旧版本对所有身份均返回 404；管理员队列仅保留举报说明、目标 ID 与处理状态，不以公开历史端点绕过隐藏状态。数据库仍保留软删除内容和修订用于审计及备份，维护者须另行确定合法的保留与清理期限。
- 账号 API 新增 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和 `Referrer-Policy: strict-origin-when-cross-origin`。现有账号配置继续使用可信来源白名单，并在生产环境启用安全 Cookie。
- 生产环境的邮件、密码重置、验证邮件、第三方登录配置和主机/反向代理防护未从本地代码推断；需在发布前由维护者逐项确认，不能从本地构建结果推断生产配置正确。

## 收录与键盘访问

- 主站提供静态 canonical 与 Open Graph 元数据；hash 路由统一 canonical 到正式站首页。站点地图仅列出当前确定的正式站首页、隐私政策和服务条款，不把未验证的动态帖子或课程路由伪装成可索引页面。
- 全局应用新增“跳转到主要内容”键盘链接，主内容区域可被程序化聚焦。完整无障碍审计仍未完成；颜色对比、屏幕阅读器读序、复杂三维实验键盘操作和移动端实际设备测试需人工复核。
