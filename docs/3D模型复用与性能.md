# 3D 模型复用与性能

## 当前实现

首页的地球圈层、水循环、地貌沙盘分别展示不同的地理过程。它们共用 `BaseScene` 管理场景、相机、灯光、渲染器和资源释放；每个教学模块只提供自己的几何结构与交互参数。`ModelQuality` 为三者提供相同的设备画质预算。教材章节或实验预设只传参数，不复制一整套渲染引擎。

这形成三层可复用结构：基础场景（母模型）、地球／水循环／地貌过程模块、章节和实验预设。地球的圈层、河流的流动和地形的侵蚀仍由各自模块表达，避免用同一个外形误导教学。

## 已实施的优化

- 低配置设备使用 1 倍像素密度，地貌概览网格从 128×128 个分段降至 64×64 个分段，约减少 75% 的网格单元；高配置保留原精度。
- 地貌噪声的固定查找表在模块加载时只创建一次，不再随每个顶点重复创建。
- 水循环的 32 棵树和 16 个云团分别合为一个 `InstancedMesh`，保留各实例的位置，理论上减少 46 次独立物体绘制提交。
- 水循环的蒸发、水汽输送、降水粒子按设备预算缩放；地球圈层球体按预算选择细分数。
- 无后期效果的场景直接渲染；只有启用后期效果时才创建合成器及其渲染目标。

## 开源选型

- [Three.js](https://github.com/mrdoob/three.js)（MIT）：现有引擎，原生 `InstancedMesh` 和场景管理足以覆盖这次优化。其[实例化文档](https://threejs.org/docs/pages/InstancedMesh.html)说明了减少绘制调用的用途。
- [three-globe](https://github.com/vasturiano/three-globe)（MIT）：适合未来地球球面数据图层、弧线、点位；当前三个教学模型中水循环和地貌属于局部剖面与地形，暂不引入此依赖。
- [Three.js LOD](https://threejs.org/docs/pages/LOD.html)：适合未来有多个现成网格精度的模型。当前程序生成的地形使用设备预算更直接。

后续引入开源模型或插件时，先核对许可证和素材来源，再比较压缩后体积、首帧时间、绘制次数、显存与移动端清晰度。不要只凭包名或下载次数替换现有教学模型。

## 验证

运行 `pnpm test` 和 `pnpm build`；浏览器检查三个主推模型的打开、模式切换与控制条。上述网格和绘制次数是结构计算值，实际帧率会受设备与浏览器影响。
