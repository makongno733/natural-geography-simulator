# 账号与课程助手：第一阶段

## 已实现

- 地理主站保持 Vue/Vite 静态构建，账号与评论使用独立 Node 服务。
- `account.kongnoma279.com` 提供账号页面和 `/api/*`，`geo.kongnoma279.com` 继续提供教材页面。
- 邮箱注册、验证、登录和密码重设；Google、GitHub OAuth；同一账号可使用多个登录方式。
- 每节教材的评论列表、登录后发表评论、删除自己的评论；每用户每分钟最多 3 条。
- 右下角课程助手从现有教材目录中查找章节，并可打开当前章节评论。模型问答尚未接入。

## 上线前配置

1. 在 Cloudflare 给 `account.kongnoma279.com` 配置指向账号服务器的 DNS 记录；确认这台服务器实际公网地址后再填写，不使用历史地址猜测。
2. 在服务器上为该子域名启用 HTTPS。Nginx 将该域名反向代理到 `127.0.0.1:4100`；账号服务会提供独立构建的 `dist-account` 页面和 `/api/*`。Cloudflare DNS 当前将 `geo.kongnoma279.com` 指向 `natural-geography-simulator.pages.dev`，主站由 Cloudflare Pages 提供服务。
   `deploy/account/nginx-site.conf.example` 提供了完整的 HTTP 跳转、ACME 验证路径和 HTTPS 代理模板；证书签发成功之前不要启用含 443 的配置文件。新增站点前先运行 `nginx -t`，启用后再重新检查，避免影响已有站点。
3. 根据 `.env.example` 在服务器创建私有 `.env`。账号数据库文件和 `.env` 不放入公开静态目录。`BETTER_AUTH_SECRET` 使用独立随机值并妥善备份。
   服务器 Node.js 需要 22 或更新版本；`better-sqlite3` 安装时需允许编译或下载官方预构建模块。
4. 配置 SMTP 后才开启邮箱注册。Google OAuth 的授权回调是 `https://account.kongnoma279.com/api/auth/callback/google`；GitHub 对应 `/api/auth/callback/github`。客户端密钥只写入服务器 `.env`。
   若使用 Resend，建议单独验证 `notify.kongnoma279.com` 用于账号邮件，避免改动主域名已有的收件记录。验证后创建仅用于发送邮件的 API Key。SMTP 配置为 `smtp.resend.com:587`、用户名 `resend`、密码为该 API Key；发件地址可使用 `no-reply@notify.kongnoma279.com`。密钥不要写入仓库或聊天记录。
5. 账号服务验收后，先确认 Cloudflare Pages 项目的实际源码和构建设置，再在该项目的构建环境中设置 `VITE_ACCOUNT_ORIGIN=https://account.kongnoma279.com`，重新构建并发布主站。仓库中的 `.node-version` 指定 Node 22。变量未设置时主站不会显示登录和评论入口。仓库现有的 GitHub Pages 工作流不应被误认为当前 `geo` 域名的发布链路。
6. 仓库提供 `deploy/account/Dockerfile` 和独立的 `deploy/account/compose.yaml`。在确认服务器端口 4100 空闲且不会影响现有服务后，先构建镜像，再用同一 Compose 项目执行一次 `node server/migrate.mjs`，最后启动账号容器。容器的 4100 端口仅映射到服务器的 `127.0.0.1`，数据库使用独立的 `account_data` 卷。定期备份该卷。

首次迁移与启动命令（在仓库根目录运行）：

```sh
docker compose -f deploy/account/compose.yaml build account
docker compose -f deploy/account/compose.yaml run --rm --no-deps account node server/migrate.mjs
docker compose -f deploy/account/compose.yaml up -d account
```

截至 2026-10-10，账号服务已在服务器的 `/opt/geo-account` 独立目录运行，数据库使用独立 Docker 卷。`account.kongnoma279.com` 已配置 Cloudflare DNS、独立的 Cloudflare Origin Certificate 和 Nginx HTTPS 代理，公网账号页可打开。`notify.kongnoma279.com` 已通过 Resend 域名验证，服务器 SMTP 连接与认证已通过；邮箱注册和重设密码尚待真实收信验收。`geo.kongnoma279.com` 已发布账号入口、课程助手、章节评论、隐私政策和服务条款，公网已验证章节搜索、跳转、空评论区加载及政策页面可访问。Google OAuth 凭据已配置，使用站长 Google 账号完成真实回调并在账号中心确认会话；Google 应用仍处测试状态，公开发布尚待用户确认。GitHub OAuth 应用与客户端密钥已配置在服务器私有 `.env` 中，公网 `/api/config` 返回 `github: true`，账号页已显示 GitHub 登录入口。站长 GitHub 账号完成了真实授权回调，账号中心确认已登录。服务器当前使用 Cloudflare 全站 `Full` 模式，尚未切换为 `Full (strict)`；调整全站模式之前须检查其他子域名的源站证书。

## 本地联调

将 `.env.example` 复制为 `.env`，把两个域名改为 `http://127.0.0.1:4173` 和 `http://127.0.0.1:4100`，`NODE_ENV=development`，数据库使用私有本地路径。填入至少一种登录方式的配置后：

```sh
pnpm account:migrate
pnpm account:dev
pnpm dev
```

账号服务只监听 `127.0.0.1`。账号入口为 `http://127.0.0.1:4100/`，课程站为 `http://127.0.0.1:4173/#/`。账号服务需有按相同 `VITE_*` 配置构建的 `dist-account`。
