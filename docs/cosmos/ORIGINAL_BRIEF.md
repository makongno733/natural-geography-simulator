# 四、重点模块：弦理论与超弦理论

**这是整个项目的重点开发部分。必须投入明显高于其他模块的内容深度、交互设计与开发资源。**

不能只用“宇宙由振动的弦组成”来概括弦理论。

需要让学习者理解：

为什么物理学家提出弦理论？

它试图解决什么问题？

它如何描述基本粒子？

为什么需要额外维度？

为什么出现超对称？

五种超弦理论之间是什么关系？

M理论是什么？

为什么弦理论至今尚未获得直接实验证实？

## D1. 弦理论的提出背景

从以下问题开始：

- 标准模型的成功与局限
- 广义相对论与量子理论的关系
- 引力量子化的困难
- 点粒子描述及相关问题
- 量子引力的研究目标
- 弦理论的发展历史

介绍：

- 维内齐亚振幅
- 早期强相互作用研究
- 弦理论向量子引力候选理论的发展
- 第一、第二次超弦革命
- 现代弦理论研究方向

## D2. 弦的基本物理

重点讲解：

- 点粒子与一维弦
- 开弦
- 闭弦
- 弦的振动模态
- 弦张力
- 弦长尺度
- 世界线与世界面
- Nambu–Goto作用量
- Polyakov作用量
- 弦的经典运动方程
- 弦的量子化概念
- 弦的激发态与粒子谱

必须解释为什么不同振动模态可以对应不同的粒子态，而不是把它简化成声音或普通机械振动。

## D3. 弦理论中的引力

解释：

- 闭弦激发态与自旋2粒子
- 引力子的理论角色

- 有效场论与低能极限
- 弦理论和广义相对论之间的联系

## D4. 玻色弦理论

- 量子一致性条件

## D5. 超弦理论

## D11. 弦理论的争议与局限

必须设置独立章节，严肃讨论：

# 九、视觉设计与交互体验

## 设计定位

整体采用：

**现代天文台 + 理论物理研究中心 + 交互科学博物馆**

设计关键词：

深空、精密、克制、学术、未来感、探索感、空间层次。

不要使用大量无意义的霓虹光效。

不要把所有内容堆在同一张巨大背景图上。

## 页面布局

首页应具有：

1. 宇宙主题视觉入口
2. 可探索的知识宇宙地图
3. 理论分类导航
4. 重点专题入口
5. 弦理论交互展示
6. 最新研究与观测资料入口
7. 推荐学习路径

知识文章页面应采用：

左侧章节导航 + 中间正文 + 右侧公式或术语辅助栏。

移动端应转换为适当的折叠导航。

## 视觉与技术

优先考虑：

- Vue 3
- TypeScript
- Three.js
- TresJS（评估兼容性后决定）
- KaTeX
- ECharts 或其他合适图表方案
- WebGL
- SVG
- CSS 动画

不得为了视觉效果引入大量重复或不必要的依赖。

复杂三维场景应按需加载，低性能设备提供降级方案。

# 十、专业知识质量控制

这部分非常重要。

网站面向大学生、教师、科研人员和科学爱好者，必须避免误导。

每个重要理论应标注科学地位，例如：

- 已获得充分实验或观测支持
- 成熟理论框架
- 尚未证实的理论候选
- 研究中的模型
- 推测性假说

例如：

广义相对论：成熟且经过大量实验检验的引力理论。

ΛCDM：目前广泛使用、获得大量观测支持的标准宇宙学模型，但仍存在未解决问题。

弦理论：具有丰富数学成果、尚缺乏直接实验证实的量子引力候选框架。

多宇宙假说：包含不同来源、不同可检验程度的理论设想，不能笼统宣称已被证实。

每篇专业文章必须具有：

- 学习目标
- 前置知识
- 核心概念
- 理论解释
- 关键公式
- 公式符号说明
- 适用条件
- 可交互示例
- 常见误区
- 延伸阅读
- 参考文献

禁止编造论文、实验结果和科学家言论。

# 十三、工程开发要求

第一阶段：项目审查

检查：

- 现有路由结构
- 页面组件
- 样式体系
- 数据来源
- 服务器接口
- Git 状态
- 构建流程
- 现有测试

第二阶段：架构设计

建立独立的 Cosmos 模块。

尽量采用数据驱动的知识章节结构。

将理论内容、数学公式、引用资料和页面组件分离，方便以后扩展。

第三阶段：核心开发

优先完成：

1. Cosmos 首页
2. 全局知识导航
3. 弦理论专题首页
4. 弦理论基础章节
5. 狭义与广义相对论章节
6. 宇宙学基础章节
7. 粒子物理图谱
8. 至少两个真正可操作的交互实验

第四阶段：专业内容扩充

逐步完成其余专题，确保每一章都有实质内容。

不要用大量空白占位页面假装完成开发。

第五阶段：质量检查

必须检查：

- 数学公式正确性
- 理论描述准确性
- 引用有效性
- 路由可访问性
- 移动端布局
- 交互可操作性
- 无障碍访问
- 性能与内存占用
- 深色和浅色模式
- 与现有 GEO 网站的兼容性

运行项目已有测试，并进行生产构建验证。

# 十四、工作方式

不要只回复一份开发建议或设计方案。

你需要在能够访问的真实项目仓库中实际开展开发。

但必须遵守以下规则：

1. 首先确认项目目录和当前 Git 状态。
2. 保留已有地理教学、社区和三维地球等功能。
3. 不要随意重构无关模块。
4. 不要覆盖用户尚未提交的修改。
5. 按模块逐步实现，避免一次性生成大量无法维护的代码。
6. 对科学计算编写必要的单元测试。
7. 对重要知识点进行事实核验。
8. 每完成一个阶段，说明新增内容、修改文件、测试结果和未完成事项。
9. 未经明确授权，不要直接部署生产环境。
10. 不得声称尚未实现的功能已经完成。

如果任务规模超过一次工作能够完成的范围，优先交付一个架构完整、内容扎实、可正常运行的第一版本，并明确后续开发计划。

# 十五、最终验收标准

最终的 GEO COSMOS 应当具备以下能力：

**对于普通访客：**

可以通过直观的交互理解宇宙、时间、空间、粒子与基本物理规律。

**对于大学生：**

可以系统学习相对论、宇宙学、粒子物理与弦理论，理解公式的物理意义。

**对于专业学习者：**

可以进一步阅读理论推导、比较不同模型、查询原始参考文献。

**对于教师：**

可以直接调用知识图谱、实验模拟与教学问题组织课堂。

**对于网站维护者：**

可以持续增加新的科学专题，而不需要反复重写整个网站。

最重要的目标：

**将 GEO 从以地理知识为核心的网站，扩展为一个连接地球科学、天文学、宇宙学与基础物理的综合科学探索平台。**

现在开始检查项目，并在确保现有功能安全的前提下，开展第一阶段的实际开发。
