# 地理共同体 · 700 独立访客／日运维监控与故障恢复手册

本手册面向站点维护者（站主），说明日常访问趋势查看位置、健康检查与外部数据源故障识别方法，以及出现线上问题时如何在 3 分钟内回退到上一可用版本。

## 一、架构与服务边界（4 类负载隔离）

1. **静态主站与 3D 交互实验（`https://geo.kongnoma279.com`）**
   - **承载层**：Cloudflare Pages 全球 CDN（主站）+ GitHub Pages（镜像站，自动重定向至主域名）。
   - **包含内容**：社区首屏、初高中/大学教材、29 个 Three.js 3D 实验、城市内涝水文仿真、静态离线回退示例。
   - **特点**：纯静态资产（Gzip 入口约 `70.9 KB`），即使后端账号服务或外部遥感接口完全不可用，访客仍可正常完成 3D 实验、教材阅读、内涝对照、证据卡生成与链接分享。
2. **账号、社区与探究后端服务（`https://account.kongnoma279.com`）**
   - **承载层**：独立服务器 Docker Compose / Node.js 22 + Express 5 + SQLite WAL（`better-sqlite3`）。
   - **包含内容**：登录注册（`better-auth`）、社区发帖/回复/全文检索（FTS5）、点赞收藏、违规举报工单、探究作业提交与教师批阅。
3. **外部遥感瓦片服务（浏览器直连 NASA GIBS）**
   - **承载层**：`https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/...`
   - **降级机制**：当校园网拦截或 NASA 瓦片超时，`SatelliteCompare.vue` 自动垫底展示标明来源与日期的内置教学示例图层，并提供「重新尝试加载实时瓦片」按钮。
4. **外部自然事件源（后端定时同步 USGS 地震目录 & NASA EONET）**
   - **承载层**：后端 `server/geo-events.mjs`（每 60 分钟同步）与 `server/hot-topics.mjs`（每 30 分钟同步），失败后启用 5 分钟退避（`RETRY_MS = 5 min`），绝不阻塞前端用户请求，直接返回 SQLite 最近一次有效缓存。

## 三、故障发生时：3 步定位受影响服务

当收到用户反馈或发现异常时，按以下顺序在 **60 秒内** 判断故障点：

1. **第一步：打开 `https://geo.kongnoma279.com/#/`**
   - 若首页白屏或静态 JS/CSS 404 → **静态主站发布异常**（见第四节 4.1 回退主站）。
   - 若首页、教材、3D 实验均可操作，仅社区显示「云端服务暂未连接 / 学术演示模式」 → **账号后端服务异常**（见第二步）。
2. **第二步：检查 `https://account.kongnoma279.com/api/health`**
   - 若超时、返回 `502 Bad Gateway` 或 `{"status":"error","db":"unavailable"}` → **后端容器或 SQLite 挂载异常**（见第四节 4.2 恢复后端）。
   - 若 `status: "ok"`、`db: "ok"`，但 `sources.geoEvents.status === "error"` 或 `sources.hotTopics` 含 `"error"` → **仅外部 USGS / NASA EONET 接口网络波动**。此时站点会自动展示上次缓存记录并标注同步时间，**无需重启服务**，等待外部接口恢复即可。
3. **第三步：检查卫星卷帘页 `https://geo.kongnoma279.com/#/geo-labs/satellite`**
   - 若提示「NASA GIBS 实时卫星瓦片暂时无法加载」 → 用户端网络无法连接 NASA 服务器，页面已自动降级为内置标注示例图层，不影响课堂教学。

## 四、如何快速回到上一可用版本（回退手册）

### 4.1 静态主站（Cloudflare Pages / GitHub `main`）回退
- **方法 A（Cloudflare Pages 控制台一键回滚，最快，30 秒生效）**：
  1. 登录 Cloudflare Dashboard → **Workers & Pages** → 选择 `geo.kongnoma279.com` 项目。
  2. 在 **Deployments** 列表中找到上一条状态正常的生产部署（例如提交 `8893561d` 或 `9a601ae2`）。
  3. 点击右侧菜单 `...` → **Rollback to this deployment**。
- **方法 B（Git 仓库 Revert 回退，同步更新 Cloudflare 与 GitHub Pages）**：
  ```bash
  git checkout main
  git pull --ff-only origin main
  git revert -m 1 HEAD --no-edit
  git push origin main
  ```

### 4.2 账号与社区后端（`account.kongnoma279.com`）恢复与数据库回退
1. **查看容器日志与重启服务**：
   ```bash
   docker compose -f deploy/account/compose.yaml logs --tail=100
   docker compose -f deploy/account/compose.yaml restart
   ```
2. **从备份恢复 SQLite 数据库**（升级前备份位于 `/opt/geo-account-backups/`）：
   ```bash
   # 1. 停止账号容器防止写入冲突
   docker compose -f deploy/account/compose.yaml stop
   # 2. 校验备份文件完整性（应输出 ok）
   sqlite3 /opt/geo-account-backups/account-pre-a20f958.sqlite "PRAGMA integrity_check;"
   # 3. 覆盖恢复数据卷中的 sqlite 文件并重启
   cp /opt/geo-account-backups/account-pre-a20f958.sqlite /var/lib/geo-account/account.sqlite
   rm -f /var/lib/geo-account/account.sqlite-wal /var/lib/geo-account/account.sqlite-shm
   docker compose -f deploy/account/compose.yaml up -d
   # 4. 验证健康检查
   curl -s https://account.kongnoma279.com/api/health
   ```
