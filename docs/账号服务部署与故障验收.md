# 账号服务部署与故障验收

前端静态站与阿里云账号服务独立发布。GitHub 推送成功不能证明账号服务容器已升级。

## 2026-11-26 个人主页故障

线上旧数据库缺少社区新字段，个人主页、帖子详情和资源查询失败。旧容器启动命令没有完整执行迁移；`/api/health` 只检查进程能否访问数据库，不能发现缺字段。

`server/index.mjs` 与 `server/migrate.mjs` 现在共用数据库初始化：先执行 Better Auth 迁移，再在事务内执行应用迁移与结构检查。失败不监听端口。应用迁移失败会回滚同批应用结构变化；Better Auth 迁移不在该事务内。

`GET /api/ready` 检查社区、个人主页、繁星及账号相关表列，返回当前镜像的 `APP_REVISION`；结构不完整返回 503。它不代表邮件投递或第三方文献服务可用。容器健康检查使用此接口。

## 升级

源码完整、干净的 main 检出目录中执行：

```bash
bash deploy/account/update-account-service.sh
```

脚本依次保存旧镜像、在线备份 SQLite 并检查备份完整性、构建、迁移、替换服务、等待就绪、执行只读业务验收。备份默认在 `/opt/geo-account-backups`，也可用 `ACCOUNT_BACKUP_DIR` 指定。并发部署由目录锁阻止；异常终止遗留锁时应先确认没有部署进程，再人工解除。

生产部署前仍需在备份副本试迁移，确认幂等性、记录数与完整性。不要在真实数据上运行写入型测试。脚本只读验收已有帖子、作者主页、资源和课题，不创建测试数据。

磁盘不足 2 GiB 时完整构建会停止，不自动清理镜像或卷。可使用已核验、依赖兼容且写入准确 `APP_REVISION` 的预构建镜像：

```bash
APP_REVISION=<完整提交号> ACCOUNT_PREBUILT_IMAGE=<镜像标签> bash deploy/account/update-account-service.sh
```

非 Git 部署目录必须显式提供源码提交号。脚本验收容器实际返回的提交号，避免新标签仍指向旧容器。

失败会尝试切回旧镜像；数据库不自动还原，以免覆盖部署期间的新写入。当前应用迁移为加法迁移；将来破坏性迁移需另行设计兼容回退。保留完整备份，在确认维护窗口及写入情况后才人工恢复。没有运行中的旧服务时，本脚本不创建旧数据库备份，应先人工备份已有数据卷。

## 只读验收

```bash
EXPECTED_APP_REVISION=<完整提交号> node server/verify-deployment.mjs
```

默认检查本机 4100 端口。检查 `/api/ready`、配置、帖子列表、资源列表、课题列表；有帖子时继续检查真实帖子详情和作者主页，有课题时检查详情。外部域名、浏览器个人主页及数据库记录数应另行复核。

自动化回归：`scripts/account-startup.test.mjs` 覆盖旧库启动、保留原数据、结构损坏和失败回滚；`scripts/account-deploy.test.mjs` 覆盖升级次序、迁移失败与业务失败回退；`scripts/deployment-verification.test.mjs` 覆盖版本、响应格式与个人主页异常。
