# 地理创新探究中心：发布复核（2026-10-18）

此文档更新先前的交付报告；先前报告描述的是发布前快照，不能作为当前上线状态的证据。

## 安全修正

- 学生班级只能由管理员写入 `student_class_enrollment`；学生提交请求中的 `classCode` 不决定教师可见范围。未分班作品只对学生本人和管理员可见。
- 教师列表与批阅均按真实提交的班级和任务授权；草稿不进入教师列表。批阅接口拒绝请求任务编号与作品任务编号不一致的请求。
- 公开展示接口仅返回标记为教研演示的样例。真实学生自由文本暂不进入公开展示；复核流程上线前，即使学生勾选知情意向，教师也无法公开发布。
- 学生重新提交会撤下旧版展示状态。教师工作台只从服务端读取授权作品，演示样例单独标识；云端批阅失败会显示失败，不再伪装成本地成功。
- 新增一次性管理员初始化脚本：仅接受数据库中已有账号的 ID 与匹配邮箱，且数据库尚无管理员时可运行，操作写入审计记录。

## 账号服务发布与验收

账号 API 独立部署，不随静态站点或 GitHub Pages 工作流自动更新。先确认服务器真实连接、持久化卷和现有用户表，备份数据库，再在 `/opt/geo-account` 用仓库既有 `deploy/account/compose.yaml` 构建镜像、运行 `node server/migrate.mjs`、启动服务。使用真实站长账号的 ID 与邮箱运行 `node server/provision-inquiry-admin.mjs <existing-user-id> <matching-email>`。管理员随后通过 `/api/inquiry/admin/assign-student` 与 `/api/inquiry/admin/assign-teacher` 分配班级和教师任务。

验收必须确认 `/api/geo-events` 返回 `earthquakes` 和 `fetchedAt`，并以真实学生、未授权教师、授权教师三个独立会话检验提交、权限、批阅和回看。公开展示应仅有演示样例。未完成这些步骤前，不能宣称探究中心的云端教学闭环已经上线。
